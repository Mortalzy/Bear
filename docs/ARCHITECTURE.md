# Архитектура BEAR

Монорепозиторий npm workspaces: React/Vite (`client`), Express (`server`), общие ограничения (`shared`). Vite передаёт `/api` на Express. На сервере Nginx или аналог должен выдавать `client/dist` и проксировать `/api` в Node. Файлы заявок временно хранятся за пределами публичной директории и удаляются после отправки письма.

## API

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/health` | Состояние процесса и флаг настройки приёма заявок |
| GET | `/api/config` | Флаг и публичные ограничения файлов |
| POST | `/api/requests` | Multipart: `name`, `phone`, `email`, `description`, `consent=true`, `files` (необязательно); 201 после принятия SMTP |

Общий лимитер применяется ко всем путям `/api`. При POST дополнительно проверяются частота обращений с IP, конфигурация, число активных заявок и заявленный размер тела. Во время загрузки сервер считает реальные байты, включая chunked-запросы, и прерывает соединение при превышении 201 МБ или 120 секунд. Multer отклоняет недопустимые расширения до записи, записывает до десяти файлов под случайными именами. Общая проверка допускает ровно 25 МБ на отдельный файл и ровно 200 МБ на всю подборку; 1 МБ = 1 000 000 байт. Лимит Multer на 1 байт выше предела файла, чтобы сигнал Busboy при достижении лимита не отклонял ровно 25 МБ; недопустимый размер проверяется до отправки письма. Лимит частей multipart учитывает десять файлов и пять текстовых полей. Сервер проверяет поля, согласие, суммарный размер и сигнатуры форматов. Все допустимые файлы прикладываются к письму Nodemailer через путь на диске. Имя файла декодируется как UTF-8, текст письма передаётся с явным кодированием. После принятия SMTP временные файлы удаляются. При явной ошибке отправки файлы также удаляются, клиент получает ошибку вместо подтверждения. Осиротевшие загрузки очищаются через сутки.

Письмо подтверждает принятие SMTP, но не гарантирует доставку во «Входящие». Лимит загрузки не отменяет ограничения размера письма у SMTP и получателя; кодирование вложений увеличивает размер письма. При отказе почтового сервиса API возвращает ошибку отправки. При обрыве соединения после принятия письма возможен повтор заявки; отдельный механизм дедупликации пока не реализован. Лимиты частоты и параллельных загрузок действуют внутри одного процесса, поэтому несколько Node-процессов требуют общего ограничения. Секреты — только в `server/.env`; логирование не включает поля заявки или пароль. Минимальная защита и шаблон Nginx описаны в [SECURITY.md](SECURITY.md).

Перед публикацией: HTTPS, приватный каталог `UPLOAD_DIR`, доступный только серверному процессу, проверка текста обработки персональных данных, реальный тест доставки SMTP, заполнение реквизитов компании и снятие `noindex` после проверки контента.
