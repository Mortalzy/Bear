# Архитектура BEAR

Монорепозиторий npm workspaces: React/Vite (`client`), Express (`server`), общие ограничения (`shared`). Vite передаёт `/api` на Express. На сервере Nginx или аналог должен выдавать `client/dist` и проксировать `/api` в Node. Файлы заявок временно хранятся за пределами публичной директории и удаляются после отправки письма.

## API

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/health` | Состояние процесса и флаг настройки приёма заявок |
| GET | `/api/config` | Флаг и публичные ограничения файлов |
| POST | `/api/requests` | Multipart: `name`, `phone`, `email`, `description`, `consent=true`, `files` (необязательно); 201 после принятия SMTP |

При POST сначала проверяются конфигурация, частота обращений и общий размер тела. Multer записывает до пяти файлов с пределами 25 МБ на файл и 18 МБ суммарно под случайными именами. Сервер проверяет поля, согласие и сигнатуры форматов. Все допустимые файлы прикладываются к письму Nodemailer через путь на диске. Имя файла декодируется как UTF-8, текст письма передаётся с явным кодированием. После принятия SMTP временные файлы удаляются. При явной ошибке отправки файлы также удаляются, клиент получает ошибку вместо подтверждения. Осиротевшие загрузки очищаются через сутки.

Письмо подтверждает принятие SMTP, но не гарантирует доставку во «Входящие». При обрыве соединения после принятия письма возможен повтор заявки; отдельный механизм дедупликации пока не реализован. Лимиты частоты и параллельных загрузок действуют внутри одного процесса, поэтому несколько Node-процессов требуют общего ограничения. Секреты — только в `server/.env`; логирование не включает поля заявки или пароль.

Перед публикацией: HTTPS, приватный каталог `UPLOAD_DIR`, доступный только серверному процессу, проверка текста обработки персональных данных, реальный тест доставки SMTP, заполнение реквизитов компании и снятие `noindex` после проверки контента.
