# Архитектура BEAR

Монорепозиторий npm workspaces: React/Vite (`client`), Express (`server`), общие ограничения (`shared`). Vite передаёт `/api`, `/privacy` и `/consent` на Express. На сервере Nginx или аналог должен выдавать `client/dist` и проксировать `/api`, `/privacy`, `/consent` в Node. Файлы заявок временно хранятся за пределами публичной директории и удаляются после отправки письма.

## API

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/health` | Состояние процесса и флаг настройки приёма заявок |
| GET | `/api/config` | Флаг, ограничения файлов и текущая версия документов |
| GET | `/privacy`, `/consent` | Серверные HTML-страницы документов, не требуют JavaScript |
| POST | `/api/requests` | Multipart: `name`, `phone`, `email`, `description`, `consent=true`, `consentRevision`, `files` (необязательно); 201 после принятия SMTP |

При POST сначала проверяются SMTP и подтверждения владельца, HTTPS/Origin в production, заголовок `X-Bear-Consent` с текущей версией, частота обращений и размер тела. Multer записывает до пяти файлов с пределами 25 МБ на файл и 18 МБ суммарно под случайными именами. Сервер проверяет поля, согласие и сигнатуры форматов. Перед передачей заявки закрытый журнал `CONSENT_DIR` сохраняет email, номер, время, полный текст согласия и политики, версию и контрольную сумму полей заявки/метаданных файлов. Ошибка журнала останавливает отправку. Все допустимые файлы прикладываются к письму Nodemailer через путь на диске. Имя файла декодируется как UTF-8, текст письма передаётся с явным кодированием. После принятия SMTP временные файлы удаляются. При явной ошибке отправки файлы также удаляются, клиент получает ошибку вместо подтверждения. Остатки старше суток очищаются при запуске и по расписанию; при ежедневном запуске максимальная задержка около 48 часов. Журнал планово очищается после 89 дней с запасом до предела 90 дней. При отзыве или достижении цели оператор удаляет записи досрочно.

Письмо подтверждает принятие SMTP, но не гарантирует доставку во «Входящие». При обрыве соединения после принятия письма возможен повтор заявки; отдельный механизм дедупликации пока не реализован. Лимиты частоты и параллельных загрузок действуют внутри одного процесса, поэтому несколько Node-процессов требуют общего ограничения. Секреты — только в `server/.env`; логирование не включает поля заявки или пароль.

Перед публикацией выполнить `docs/PRIVACY_LAUNCH.md`. Каталоги `UPLOAD_DIR` и `CONSENT_DIR` должны быть закрыты и размещены в РФ вместе с почтой и копиями. Удаление писем и документирование уничтожения выполняет владелец. Пример HTTPS-прокси находится в `docs/nginx.conf.example`; снимайте `noindex` только после подготовки и проверки запуска.
