# Архитектура BEAR

Монорепозиторий npm workspaces: React/Vite (`client`), Express (`server`), общие ограничения (`shared`). Vite передаёт `/api` на Express. На сервере Nginx или аналог должен выдавать `client/dist` и проксировать `/api` в Node. Файлы заявок хранятся на постоянном диске за пределами публичной директории.

## API

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/health` | Состояние процесса и флаг настройки приёма заявок |
| GET | `/api/config` | Флаг и публичные ограничения файлов |
| POST | `/api/requests` | Multipart: `name`, `phone`, `email`, `description`, `consent=true`, `files` (необязательно); 201 после принятия SMTP |
| GET | `/api/files/:requestId/:fileId/:token` | Скачивание вложения по секретной ссылке до истечения 30 дней |

При POST сначала проверяются конфигурация, частота обращений и общий размер тела. Multer записывает до пяти файлов по 50 000 000 байт под случайными именами. Сервер проверяет данные и первые байты форматов, сохраняет хеши секретных токенов, затем отправляет письмо со ссылками. При явной ошибке удаляет файлы. Письмо подтверждает принятие SMTP, но не гарантирует доставку во «Входящие». При обрыве соединения после принятия письма возможен повтор заявки; отдельный механизм дедупликации пока не реализован.

Ссылки содержат случайный токен и действуют 30 дней; файл отдаётся как attachment с `nosniff`. Очистка запускается при старте и раз в сутки. Лимиты частоты и параллельных загрузок действуют внутри одного процесса, поэтому несколько Node-процессов требуют общего ограничения и общего файлового хранилища. Секреты — только в `server/.env`; логирование не включает поля заявки, токены или пароль.

Перед публикацией: HTTPS, постоянный том для `UPLOAD_DIR`, резервирование и доступ к нему только серверному процессу, проверка текста обработки персональных данных, реальный тест доставки SMTP, заполнение реквизитов компании и снятие `noindex` после проверки контента.
